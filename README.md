# Datagrid — AI Data Analytics Platform

Upload any dataset — or connect a database, or drop in a ZIP of several
files — and get automatic cleaning, profiling, an interactive BI dashboard,
a real SQL editor, a full Excel workbook export, business reports (Markdown/
HTML/PDF), and an AI data analyst chat. Powered by the Groq API.
No machine learning, no forecasting: this is analytics/BI only.

## Features

**Dashboard experience**
- Dark/light mode toggle (persisted client-side)
- Toast notifications for key actions (upload, SQL queries, AI summary)
- Skeleton loaders while charts render
- KPI cards with sparklines, growth %, and trend arrows (works even without
  a date column — falls back to row-order buckets)
- Dashboard-wide search that filters the Data Preview and Column Profile tables
- Sticky topbar, glassmorphism cards

**Business Insights (no AI required)**
- Deterministic Top/Bottom Performers (by category × metric)
- Growth Opportunity signals (high-performing, low-volume segments)
- Risk Indicators (missing-data hotspots, concentration risk, duplicate rate)
- Layered underneath the on-demand AI Executive Summary

**Data sources**
- Upload CSV, Excel (.xlsx/.xls), JSON, TSV, TXT — auto-format detection
- Upload a `.zip` containing multiple files — pick which one to analyze
- Connect directly to PostgreSQL, MySQL, or SQLite and import a table

**Automatic processing**
- Cleaning: missing values, duplicates, whitespace, mixed types, placeholder
  tokens ("N/A", "null"...) — with a transparent, human-readable log
- Profiling: shape, memory, dtypes, missing %, cardinality, numeric &
  categorical summaries, a data quality score

**Dashboard**
- Auto-detected KPI cards (skips ID columns, finds real business metrics)
- 20+ auto-generated charts across 5 categories (filterable in the UI):
  histograms, box plots, violin plots, donut chart, stacked bar, correlation
  heatmap + ranking, pair plot (scatter matrix), bubble chart, missing-value
  matrix, cardinality analysis, rolling-average time series, monthly volume
- Every chart supports PNG download and a fullscreen view; AI explanations
  are available per chart when a Groq key is set

**SQL Analytics**
- Every dataset is loaded into its own SQLite database
- A real SQL editor (read-only: SELECT/WITH/EXPLAIN only)
- AI natural-language-to-SQL, AI query explanation, AI query optimization
- Query history (last 50) and named/saved favorite queries, persisted per dataset
- Chart-the-results, CSV export of results

**AI (Groq)**
- Chat with the dataset, in persistent named/renameable conversation sessions
  (list, switch, rename, delete — like a lightweight ChatGPT sidebar)
- AI-suggested follow-up questions after every chat answer
- One-click AI Executive Summary (cached so reports/exports reuse it)
- Per-chart AI explanations
- Every prompt lives in `services/prompts.py` for easy review/tuning

**Dataset Intelligence** (no AI required)
- Heuristic business-domain detection (e-commerce, finance, healthcare, HR, etc.)
- Auto-detected KPI candidate columns and possible key/ID columns
- Statistical anomaly counts (IQR method) surfaced on the Overview tab

**Exports**
- **Excel Dashboard workbook**: Dashboard sheet with native Excel charts +
  KPI cards, Summary, Pivot Tables, Clean Data, Raw Data, and an **AI Search**
  sheet (a Q&A reference generated by AI — or deterministically via pandas
  if AI is disabled — at export time)
- **Reports**: Markdown (.md), standalone HTML (opens in any browser, charts
  included), PDF (via reportlab + matplotlib, no system dependencies), and
  a structured JSON export (profile + KPIs + business insights + cleaning log)
- Raw / Clean CSV downloads

**Performance at scale**
- Histograms are pre-binned server-side (30 bins) instead of shipping every
  raw value to the browser — payload stays flat regardless of dataset size
- Box plots, violin plots, and the pair plot use a representative sample
  (with a transparent on-screen note) once a dataset gets large; KPI
  totals, histograms, and correlations always use the full dataset
- CSV parsing uses pandas' fast C engine by default, falling back to the
  lenient Python engine only for malformed files
- Verified on a 300,000-row / 22MB CSV: upload+clean+profile ≈ 4.4s,
  dashboard load ≈ 0.7s, SQL query ≈ 0.3s, Excel export ≈ 6.5s, PDF ≈ 1s

**Enterprise features**
- Pin/favorite datasets for quick access from the home page
- Keyboard shortcuts (Ctrl/Cmd+K to jump to search, Esc to close fullscreen charts)
- Rate limiting on upload and AI-backed endpoints
- Structured activity logging (uploads, queries, AI requests) with a simple
  token-gated viewer at `/admin/activity`
- In-memory caching of expensive per-dataset computations
- Paginated data preview (server-side, not just the first N rows)
- Secure filename handling, hardened session cookies

## Quick start (local)

```bash
cd analytics-platform
python -m venv .venv && source .venv/bin/activate      # optional but recommended
pip install -r requirements.txt

cp .env.example .env
# then edit .env and set GROQ_API_KEY=your_real_key
# (get one at https://console.groq.com)

python app.py
# open http://localhost:5000
```

The app works without a Groq key too — upload, cleaning, profiling,
dashboards, SQL Analytics (manual queries), and exports all function
normally. Only AI Chat, AI Executive Summary, chart explanations, and
natural-language-to-SQL require `GROQ_API_KEY`. The Excel "AI Search" sheet
and PDF/Markdown/HTML reports still generate without AI — they just use
deterministic pandas-computed answers instead of AI-written ones.

## Environment variables

All configuration lives in environment variables (see `.env.example`), never
hardcoded:

| Variable         | Required | Default                  | Purpose                          |
|------------------|----------|---------------------------|-----------------------------------|
| `GROQ_API_KEY`   | For AI   | —                          | Your Groq API key                |
| `GROQ_API_BASE`  | No       | `https://api.groq.com/openai/v1` | Groq API base URL         |
| `GROQ_MODEL`     | No       | `openai/gpt-oss-120b`     | Model used for chat/insights/SQL  |
| `SECRET_KEY`     | Yes (prod)| dev key                  | Flask session signing key         |
| `FLASK_ENV`      | No       | `production`               | `development` enables debug mode  |
| `PORT`           | No       | `5000`                     | Port the app listens on           |
| `MAX_UPLOAD_MB`  | No       | `200`                       | Max upload size                   |
| `ADMIN_TOKEN`    | No       | —                          | Enables `/admin/activity` log viewer when set |
| `FORCE_SECURE_COOKIES` | No | `0`                     | Set to `1` once served over HTTPS |

**Never commit your `.env` file.** It's already in `.gitignore`.

## Deploying

Standard Flask app served by gunicorn (`Procfile` included) — deploys as-is
to Render, Railway, Fly.io, or any VPS:

1. Push this project to a git repo.
2. On your host, set the environment variables above (especially
   `GROQ_API_KEY` and a real `SECRET_KEY`) in the platform's dashboard —
   don't upload a `.env` file to production.
3. Build command: `pip install -r requirements.txt`
4. Start command: `gunicorn app:app --bind 0.0.0.0:$PORT --workers 3 --timeout 120`

Notes for production:
- Uploaded/processed data (including each dataset's SQLite file) is stored
  on local disk (`uploads/`, `processed_data/`). Most PaaS platforms
  (Render, Railway, Fly) use **ephemeral filesystems** — files vanish on
  redeploy/restart. Fine for a demo; for real persistence, mount a
  persistent volume or swap `utils/storage.py` to write to S3/a database
  instead. The storage layer is isolated in that one file specifically so
  it's easy to swap later.
- PDF/Excel generation and larger SQL queries are CPU/memory-bound —
  gunicorn's default `--timeout 120` gives headroom; raise it further for
  very large datasets.
- **SQL Server / Oracle** database sources need extra drivers not bundled by
  default: SQL Server needs `pyodbc` + the OS-level "ODBC Driver for SQL
  Server" (`apt-get install msodbcsql18` on Debian/Ubuntu hosts, or the
  platform's equivalent); Oracle needs `oracledb` (formerly `cx_Oracle`).
  Add the pip package to `requirements.txt` and a matching entry to
  `DIALECT_DRIVERS` in `utils/db_connector.py`.
- Put this behind HTTPS (most PaaS platforms do this for you automatically).

## Notable design decisions

- **Charts are rendered server-side (matplotlib/seaborn), not with a
  client-side JS charting library.** An earlier version used Plotly.js
  loaded from a CDN; that meant every chart on the page failed identically
  whenever that CDN was blocked (corporate firewall, ad-blocker, offline
  browser) — a fragile dependency for something as core as "show me the
  data." Now every EDA chart, plus SQL Analytics result charts and the
  charts embedded in the standalone HTML report, are rendered as base64 PNG
  images with zero external requests. The tradeoff is losing client-side
  interactivity (hover tooltips, pan/zoom); given how often chart failures
  turn out to be a blocked third-party script, that's the right default.
  See `utils/chart_images.py`.
- **Read-only SQL editor.** The SQL Analytics tab only allows
  `SELECT`/`WITH`/`EXPLAIN` — this is an analysis tool, not a place to
  mutate stored data, even though it's "just" a scratch SQLite file per
  dataset.
- **No formulas in generated Excel files.** All pivot/summary values are
  computed in pandas and written as static values. That avoids `#REF!` /
  `#DIV/0!` errors on data we don't control the shape of, per the project's
  zero-formula-error requirement.
- **PDF via reportlab, not a headless browser.** WeasyPrint/wkhtmltopdf need
  system libraries (Cairo/Pango/Chromium) that aren't guaranteed on a
  minimal PaaS host. reportlab is pure Python and works identically
  everywhere `pip install` works.
- **AI Search sheet is a snapshot, not live.** A real "type a question into
  a spreadsheet cell and get an AI answer" requires Office Scripts/VBA
  calling out to an API, which isn't portable across Excel/Sheets/LibreOffice.
  Instead, a fixed set of high-value questions is answered once at export
  time (by AI if enabled, otherwise deterministically via pandas) and baked
  into the sheet as a reference.
- **ID-like columns are excluded from KPIs/charts.** Columns like
  `order_id` or `customer_id` are unique keys, not business metrics —
  summing/averaging/plotting them is meaningless, so `utils/charts.py`
  filters them out by name pattern and (for integer columns only) near-100%
  cardinality.
